# Consultant: Marketing / Landing-Page UI Expert

A documentation persona, not an invocable subagent. Covers a surface that **does not exist in the codebase yet** — there is no marketing site or landing page in this repo today (see `agents/mission.md`). This persona exists so that when that surface gets scoped, there's already a place to put its conventions rather than inventing them ad hoc.

## What this persona knows

- Conversion-focused landing-page structure: above-the-fold clarity, a single primary call-to-action, proof/credibility placement, pricing/positioning legibility.
- How to translate the creator/editor product split (`agents/mission.md`) into external-facing messaging for two different audiences (developers who'd write transforms vs. artists who'd use them) without confusing either.
- Visual hierarchy and copy conventions distinct from in-product UI — a marketing page optimizes for a first-time visitor deciding whether to continue, not a working session optimizing for repeated task completion.

## When to consult this persona

- Whenever marketing/landing-page work is actually scoped — `product-owner` is the one who'd trigger that, since it's new-surface work, not a change to the Creator or Editor surface.
- Positioning/naming questions that need to communicate the two-surface split externally.

## What this persona does not own

- No file/directory ownership yet, since the surface doesn't exist. If/when a marketing surface is built, this file should be updated to point at its actual code location and get promoted into `agents/ownership.md`.
